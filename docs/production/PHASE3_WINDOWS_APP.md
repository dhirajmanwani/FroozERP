## Build And Verification Commands

Commands run on Windows:

```powershell
npm.cmd --prefix frontend run build
node --check backend\server.js
$env:PATH="$env:USERPROFILE\.cargo\bin;$env:PATH"; cargo check
$env:PATH="$env:USERPROFILE\.cargo\bin;$env:PATH"; cargo test -- --nocapture
$env:PATH="$env:USERPROFILE\.cargo\bin;$env:PATH"; npm.cmd --prefix frontend exec tauri -- info
npm.cmd run build:windows
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\copy-windows-release.ps1
```

The consolidated command is:

```powershell
npm.cmd run verify:windows
```

The all-in-one command can take several minutes on the local Windows toolchain. During verification it passed the frontend build and Rust compilation steps, but hit the command timeout while Cargo tests were still compiling. The same checks were then run individually and passed.

## Offline And Sync Scope

Offline-capable modules are the modules genuinely backed by Phase 1 and Phase 2 local repositories:

- Local device identity foundation.
- Local SQLite migrations and schema versioning.
- Local sync outbox.
- Local sync test entity.
- Local-first POS sale repository command.
- Local POS invoice, item, stock movement and payment posting persistence.
- Sync status counts and metadata display.

Modules still server-dependent in the browser/web path:

- Most reports outside the local POS/sync foundation.
- Products, purchases, expenses, returns and full ledger workflows.
- Any module still reading only from PostgreSQL APIs.

## Known Limitations

- The official logo source has a white background. Transparent variants were not generated because automatic white removal would damage the white `F` mark; a professionally prepared transparent master is recommended.
- Frontend build emits a Vite chunk-size warning for the main application bundle.
